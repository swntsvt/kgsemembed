`git_dirty: false`. Ablation results record digests of the D1 files for

report reads the D1 P1@48 link run from `ppas_controlled/` and the D2 one from

## Re-run outcome

All 43 D1 runs completed at `66aabc3` from a clean tree (09:46–13:19,
2026-10-28, MPS, pinned M2 revision; `logs/issue164_d1_reruns.log`, no
errors). Every result passes the checks above and has its sidecar. MRR moves
by +0.0001 to +0.003 per run against the pre-#137 runs, F1 by about +0.002
to +0.003; no contrast changes sign or conclusion (P3 − P1 +0.341 → +0.343,
P4 − P3 −0.013 → −0.013, A-core − A0 +0.272 → +0.274, C+syn − A-core
−0.249 → −0.251). P1/P2 still reproduce #122's deterministic/PPAS runs
exactly. The validation report has all 19 expected runs, and the role report has all 38.

The reports under `reports/` are copies of `data/results_issue164/*/report.md`
and their figures (aggregate metrics only, no dataset text), regenerated by:

```bash
R=data/results_issue164
python scripts/generate_ppas_ablation_report.py --results_dir $R/ppas_ablation/ --output $R/ppas_ablation/report.md
python scripts/generate_ppas_ablation_report.py --results_dir $R/ppas_controlled/ --output $R/ppas_controlled/report.md
python scripts/generate_ppas_validation_report.py --reference_dir $R/ppas_controlled/ --results_dir $R/ppas_validation/
python scripts/generate_predicate_role_report.py --results_dir $R/predicate_roles/ \
    --d1_link_dir $R/ppas_controlled/ --d2_link_dir $R/ppas_validation/
```

Every D1 number in both texts comes from a result recording
`population.n_train_refs == 726`. Two D1 statements rest on selections, not
on scores, and are population-independent: the controlled representation has
no D1 text over 420 tokens (#122), and lexicographic order drops
`rdfs:label` for many trimmed candidates (#128 follow-up label-loss count,
tokenizer only). The paper cites no #134 number, and no D1 number from the
pre-#137 trees (`data/results_ppas_*`, `data/results_predicate_roles/`),
which stay as they were.
